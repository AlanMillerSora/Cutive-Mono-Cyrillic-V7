# V7 — переиспользование латинских контуров

Правило проекта: если кириллическая буква по конструкции **совпадает** с
латинской, её контур берётся из Cutive Mono, а не рисуется заново. Похожая
форма — не повод копировать; разные буквы остаются собственными.

Технически контур копируется через `DonorSource.add()`: донорский глиф
разбирается на контуры, переносится в новый Unicode-глиф и центрируется в
ячейке. Масштабирования нет (кроме старого `sx=0.95` у К, который в V7
удалён вместе с самой копией). Для составных доноров (Ë, ë, Ï, ï) контуры
раскладываются на компоненты; визуальная форма сохраняется.

## Что похоже, но не скопировано

| Пара | Почему нельзя взять латинский контур |
|---|---|
| **К / K** | донорный K — 1274 ед. ширины, стем у самого края ячейки (lsb 33), засечки 602/496. В русском тексте это самая широкая и тяжёлая буква. V7 строит К из тех же 96/396, что и остальные: 1105 ед., стем с полем 68. |
| **к / k** | у k есть выносной элемент (1182) и очень пологое плечо; обрезка верха даёт «k со спиленным выносным». V7 строит каппу в рост строчных: 986 ед., как у н. |
| **х / x** | донорный x намеренно короткий — 774 при x-height 813 (как v/w/y). В кириллице х стоит среди букв полной высоты и визуально проваливается. V7 перерисовывает х в 813 при той же ширине 920 и той же толщине 96. |
| **Б / б** | у B два счётчика; у Б один, с верхней перекладиной. б — не b: у него верхняя перекладина и выносной в рост b/h. |
| **В / в** | В = B (скопирован); в — две чаши, B не подходит. |
| **Г / г** | у G есть перекладина и шпора; Г — угол из стема и верхней перекладины. |
| **Д / д** | D — замкнутая чаша; Д — две ножки и нижняя плита. |
| **Ж / ж** | нет латинского аналога; конструкция варианта A. |
| **З / з** | S имеет терминалы сверху справа и снизу слева; у З оба терминала слева. |
| **И / и** | И — зеркальная N с диагональю; u — одна чаша. |
| **Й / й** | И + краткая; у J/Y другой низ. |
| **Л / л** | нет аналога; наклонная нога и верхняя перекладина. |
| **П / п** | нет аналога; две стойки и перекладина. |
| **У / у** | Y — «V» + прямой стем со стопой на базовой; у — два плеча и загнутый хвост ниже базовой. |
| **Ф / ф** | O + вертикальный стем; O сам по себе не подходит. |
| **Ц / ц** | нет аналога; U-тело и хвост. |
| **Ч / ч** | нет аналога; короткая левая стойка, перекладина, правая стойка. |
| **Ш / ш, Щ / щ** | нет аналога; три стойки, у Щ — хвост. |
| **Ъ / ъ, Ы / ы, Ь / ь** | ь-чаша — кириллическая конструкция; b имеет выносной и один счётчик. |
| **Э / э** | зеркальная C с перекладиной (вариант B). |
| **Ю / ю** | стем + O; O не содержит стема. |
| **Я / я** | зеркальная R (вариант C); у R другая нога и чаша. |

## Почему копии не являются «вторыми контурами»

В собранном TTF каждый кириллический глиф — самостоятельный `glyf`-запись
со своим хинтингом. Это не компонентная ссылка, но и не независимый
рисунок: контур получен из донора и совпадает с ним по форме. Такой способ
выбран потому, что:

1. ttfautohint хинтит каждый глиф отдельно; общий компонент заставил бы
   кириллицу наследовать латинские инструкции и положения.
2. Компоненты в TTF усложняют `removeOverlaps` и OTF-конвертацию.
3. Проверка `verify.py` сравнивает именно `glyf`-контуры, поэтому копия
   видна как отдельный глиф, но её форма контролируемо совпадает с донором.

Для донорских композитов (Ë, ë, Ï, ï) контуры раскладываются на компоненты;
для `р` кривые переквантуются в Q-сплайны с точностью < 16 ед. (на практике
≤ 5 ед.), визуально неотличимо.
